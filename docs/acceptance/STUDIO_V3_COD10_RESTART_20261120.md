# Studio v3 伴侣异常退出与重启后的资源留存

2026-11-20，在源码 bf0dc5f39185fe085906c914fa7cf125cff644ca 上，用 Chrome Headless Shell 151.0.7922.34 和本地 Origin 完成原生配对。密封 Docker 镜像为 sha256:76badd727406b763e562556ba9cf53b1eb642dd9657674904ef7a20fa20b1537，伴侣源码指纹为 78a4664416976fc3d597251efad692c859a4bcecbe8745a671aca0bfbcb6071b。测试使用独立 loopback 端口、虚构文本、42 秒配对期限和 15 秒空闲期限。实际运行命令的 supervisor 期限为 20 秒，anchor 期限为 57 秒。

| 检查 | 实测 |
| --- | --- |
| 崩溃前的独立记录 | Docker 清单确认实际运行中的命令 supervisor、子进程和 anchor。测试为后续核对记录了完整容器 ID、属主和工作区标签、挂载身份与精确临时卷名称。 |
| 同端口重启 | 只向测试的原伴侣 OS 子进程发送 SIGKILL。重启后，仍有 26.429 秒有效期的旧浏览器令牌收到 HTTP 401，错误为 AUTH_REJECTED。用新配对读取旧回执或关闭旧工作区均收到 HTTP 404，错误为 WORKSPACE_NOT_FOUND。 |
| 独立属主 | 替代进程创建、读取并关闭自己的工作区。核对属主不同，且该工作区的容器和卷清单回到零。旧工作区的容器和卷仍在。 |
| 进程与资源记录 | 原命令达到其 supervisor 期限后自行退出，Docker 显示状态 exited、PID 0、退出码 124，此时 anchor 仍在运行。anchor 随后同样自行退出。最后一条创建标签过期后 224 毫秒，两个停止容器和一个卷记录仍在。又一次替代进程启动后，在最后一条标签过期后 5.205 秒仍核对到同样三个记录。 |
| 测试清理 | 测试 harness 在删除前重新核对最初记录的属主、工作区、完整容器 ID 与卷身份。仅对本次已退出的两个容器和一个卷执行非强制删除。独立清单确认原工作区容器与卷均为零。 |

探针退出码为 0，验证了重启后旧授权不可复用，也复现了当前替代进程不会自动清理旧属主资源。容器进程退出、卷记录存在和卷内数据可读是三个不同的状态。本次未读取旧卷内容，未重启或停止共享 Docker daemon，未测试真实 daemon 故障恢复，也未验证自动孤儿移交或清理。运行中伴侣的正常关闭与 TTL 证据仍由 [独立核验记录](STUDIO_V3_COD10_TTL_20261120.md) 支持。
