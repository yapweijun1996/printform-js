# Studio v3 本地源码执行与产物验收

本次只验证虚构文档源码和结构化操作 JSON。G6、G7 的完整验收范围记录在[编码代理验收](../STUDIO_V3_CODING_AGENT_ACCEPTANCE.md)。生产平台、真实模型、数据许可和持续运维采用各自的验收记录。

## 修复与证据

- 受限 checkout 将源码文件保存为 `0600`。旧镜像把文件属主设为 root，再去掉写权限，导致 UID 1000 启动时读取 `identity.mjs` 返回 `EACCES`。仅为 `COPY` 指定 `0444` 的第一次修复也失败，实测 BuildKit 同时将新建的 `/opt/printform` 设为 `0444`，缺少遍历权限。最终镜像明确使用 root 所有的 `0444` 文件和 `0555` 目录。将构建上下文所有输入设为 `0600` 后重建，原隔离参数下启动并校验 sealed 源码身份通过。
- 导出仅接受真实成功的当前运行，并核对其变更记录中请求路径新增或改变的产物字节。仅成功退出、仅改文件模式或从旧树引用产物都会拒绝。相同字节的重建可复用当前原始回执，或先用独立校验的 patch 删除旧文件后再构建。独立测试结果和业务正确性仍由对应的验收检查负责。
- 工作区成功关闭后清除树、初始快照和完整命令回执。重复的旧提交意图仍返回原接收回执，完整输出只从有界工作区回执存储读取。既有授权、工作区隔离与独立人工 Preview/Apply 路径继续用于产物。

环境为 Linux/amd64、Node 24.19.0、Docker Engine 28.4.0、Playwright Chromium 151.0.7922.34。镜像 `sha256:e1e20d5004eb9a5099fee5a1e30c4e5e8168106e39f76927fea8e61f3eddf147` 使用 Node 24.21.0，启动核对的 runner 源码哈希为 `b6a89aa87b2f8ae3f17adc436fed6e47ef22c7862599bc3a76b5c509b69ef23b`。

定向 Vitest 共 9 个文件 136 项通过，常规命令中的 9 个 Docker 测试单独记录。范围包含命令/授权契约、关闭后的回执回收、严格 JSON、作用域/金额保护、候选检查、人工应用和同一候选重复应用，以及独立语料 oracle 对修改测试、缺失执行、误报 stdout、错误源码与产物身份的拒绝。候选消费者测试使用合成传输回执，实际 Docker 回执以单独运行的集成测试为准。

实际 Docker 测试两次启动失败的原始结果各为 0/9，对应上面的文件和目录权限原因。最终镜像在原隔离与超时参数下运行，8/9 项通过，总计 577.68 秒。通过项包括真实测试失败、源文件修复、构建与产物身份验证，修改源码后非零退出的对账和旧制品拒绝，无变化命令的伪构建拒绝，跨属主拒绝、输出和 BOM 字节、资源限额及撤销。Stop 和恢复一项在 31.27 秒时失败，broker 报 `DOCKER_TIMEOUT`，未达到 G6 取消验收。没有放宽超时、隔离或并行负载要求。同一镜像和所有原参数下单独重跑该项通过，测试用时 74.81 秒（含配对、创建、运行、独立容器检查和清理），其余 8 项按测试名过滤。原整组失败保留；该用时并非 COD-07 的取消延迟。结束时发现一个本次测试镜像的身份校验容器遗留在 created 状态，未挂载工作区。核对镜像、属主和挂载后仅删除此测试容器，余下工作区容器和卷为零。异常启动路径的自动资源回收尚未通过验收。

本地 `build:assets`、站点构建、3 个样本校验和 129 个代理契约示例通过。首次完整 Studio Chromium 探针完成真实配对与明确的一次性授权，随后在首个工具前提示本地工作区不可用，表单停在 `r0`，清理得到确认。在固定 Docker 用例结束后进行唯一一次带请求计时的重试。配对 POST 返回 200（19 毫秒），创建工作区 POST 在 15,040 毫秒被 Chromium 以 `net::ERR_ABORTED` 中止，与客户端现有的 15 秒请求期限一致；撤销 POST 返回 200（3,682 毫秒）。两次均未收到任何工具回执、未生成候选、未改变 `r0`，抓取只保留路由、状态和计时。探针使用合成 provider，没有提交任何正式模型评估结果。

## 低负载浏览器和 Docker 同轮复验

等待前一批高负载测试结束后，构建后的 Studio 界面使用同一份 sealed 镜像、相同客户端期限和相同沙箱参数重新执行。两次工作区创建返回 200，服务端分别测得 6,285 和 9,148 毫秒。成功完整轮次中，创建请求的 8,447 毫秒消耗在 Docker 启动工作区所需的容器创建阶段，启动命令共 474 毫秒，volume 创建 17 毫秒。上一轮 15,040 毫秒中止仍作高负载运行结果保留。

首次低负载探针已生成真实 Node 测试和构建回执、源绑定 JSON、私有候选和纸张预览。探针误点了平板预览关闭后仍留在隐藏面板中的 Apply。用界面现有的 Review in AI 入口回到面板后完整重跑通过。真实 Docker 的测试和构建退出码均为 0，独立预期 JSON 的 SHA-256 为 `a0da27d59732826824a2b84a60b37d84c4c4e15ad41ba91c8758d1ee48e4eb14`，与产物回执相同。检查私有预览前后保持 `r0`，明确点击 Apply 后变为 `r1`，预览纸张标题与预期一致。运行结束关闭工作区返回 200，318 毫秒。只有模型响应为合成脚本，此处仅计入本地机械验收。

仓库新增的 opt-in Chromium 回归用例使用部署构建 `63e4c858c92e6fab188c39b5a03b0bee4117f6a5` 及同一 Docker 镜像独立再跑，1/1 通过（41.6 秒）。测试用例导入 ESM 执行器，初次以 CommonJS 规格加载时解析失败，改用 `.spec.mjs` 后开始实际测试。可用下面的命令复验，需预先准备本地 Docker 与 Playwright Chromium。4317 端口供测试 companion 独占，站点采用仓库的 Playwright 默认本地端口。测试不上传真实模型、业务数据或配对记录，只附上去除工作区 ID 的路由、状态和计时。
